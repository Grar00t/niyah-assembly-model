# Causal attention LM: exact implemented contract

## Scope

- Tokenization: 256 possible byte IDs, output masked to bytes appearing in
  `data/corpus.txt`. Text length and vocabulary depend on the compiled
  training corpus, not a dynamic tokenizer.
- Learnable parameters: `E[256,16]`, `POS[8,16]`, `F[16,16]`,
  `FB[16]`, `O[256,16]`, `OB[256]` = 8,848 float32.
- One head. No learned Wq/Wk/Wv. For position `t`, `x_t=E[token_t]+POS[t]`;
  `q=x_7`, `k_t=v_t=x_t`, `s_t=(q dot k_t)/sqrt(16)`.
- Causal context contains only the eight tokens preceding the target byte.
  `a=softmax(s_0 ... s_7)`, `h=q+sum_t(a_t*v_t)`.
  `y=h+ReLU(F*h+FB)`, `p=softmax(O*y+OB)` (masked).
- Loss: negative log probability of the next observed byte. All derivatives
  (including softmax score/query/key/value, input embedding and feed-forward)
  are explicitly implemented in Assembly and updated with SGD, LR=0.025.
- All nonlinearities and numeric operations are native assembly, SSE and x87.
  No C runtime or model provider, no GPU, no AVX requirement, no ML libraries.
- Training weights are deterministic from xorshift32 seed 0x1234567;
  generation sample seed is independently specified.

## Verification

`make test-attention` executes a CPython *test-only* reference forward
implementation, reads raw float32 weights exported by the Assembly trainer,
and checks:

1. Statically-linked native Linux ELF lacks a dynamic interpreter.
2. Seeded training and generation are deterministic.
3. Changing only sampling RNG seed changes generated bytes.
4. Sampling obeys the corpus byte vocabulary and expected length.
5. Training loss decreases.
6. Heldout loss improves versus untrained initialization.
7. Independent Python probability calculation matches Assembly train loss.
8. Independent Python probability calculation matches Assembly heldout loss.
9. With identical trailing two bytes, earlier different context changes
   predicted probabilities (counterfactual attention-context test).
10. Saved parameters are finite.

`make attention-checkpoint verify-attention test-attention-checkpoint`
trains, checks source/data/weight SHA-256 and byte length, and checks
trained-vs-inference exact generation replay using an Assembly-only inference
ELF. `make generate-attention` uses the existing saved weights and
does not retrain.

## Limitations / what is NOT proved

- This is NOT a large language model or mature Transformer decoder:
  one head, 16-dimensional representations, eight-token context,
  identity-tied QKV, no LayerNorm, no learned tokenizer, and no stacked blocks.
- Heldout is short and linguistically very close to train, so the reported
  improvement does not support general semantic generalization.
- Text generation beyond exact training snippets is not automatically
  invention: it is conditional sampling from learned probabilities.
- No proof of memory safety, instruction-following, reasoning, hardware
  drone deployment, full UTF-8-safe generation, real GPU training, or
  model superiority.
- Checkpoint verification establishes weight/source/data integrity
  relative to the accompanying manifest; it does not establish that
  a model is safe, honest, accurate, novel, or useful.
- Training complexity and throughput for long corpora are untested.

## Next engineering gate

A future genuine multi-layer causal Transformer would require separately
verified Wq/Wk/Wv projections, normalization, multi-head attention,
feed-forward, tokenizer/weight-format contracts, checkpoint schema and
independent reference differential tests. Real TinyStories-sized training
may require a GPU and should have a cost/time estimate **before** purchase.
Do not market this 8,848-weight experiment as an LLM or conceal its scale.
